Definir, **antes de redactar** `03_SEGURIDAD.md`, el alcance y contenido del documento de seguridad de Pablito Sports.

`03_SEGURIDAD.md` debe **materializar** las decisiones de seguridad ya aprobadas en `02_ARQUITECTURA.md` y `02.1_DECISIONES_ARQUITECTONICAS.md` (`AD-37`, `AD-20`, `RN-66`, `RN-67`, `RNF-11`, `RNF-12`, `RF-28`), sin introducir nuevas reglas de negocio ni decisiones arquitectónicas.

| Aspecto | Detalle |
|---|---|
| Riesgo | `AD-37` habilita CSRF al usar cookies de sesión. |

| Excepción | API pública es anónima y de solo lectura; no requiere CSRF. |

## 4.5 XSS

| Aspecto | Detalle |
|---|---|
| Superficie | Descripciones de producto (`ADP-14` pendiente de negocio). |
| Mitigación | Escaping en renderizado; CSP restrictivo; sanitización si se permite HTML enriquecido. |
| Cookies | `HttpOnly` impide robo de sesión por XSS. |

## 4.6 SQL Injection

| Aspecto | Detalle |
|---|---|
| ORM | SQLAlchemy con consultas parametrizadas. |
| Prohibición | No concatenar valores de usuario en SQL. |
| Búsqueda de texto | Usar funciones seguras del ORM o full-text search de PostgreSQL. |

## 4.7 Upload seguro de archivos

| Aspecto | Detalle |
|---|---|
| MIME permitido | `image/jpeg`, `image/png`, `image/webp`. |
| Extensión | Coincidente con MIME; validación de doble extensión. |
| Tamaño máximo | 5 MB por archivo en v1. |
| Renombrado | Nombre aleatorio en servidor; nunca se conserva el nombre original. |
| Ubicación | Directorio fuera del raíz web; servido por Nginx. |
| Validación | Dimensiones mínimas/máximas; rechazo de archivos ejecutables. |

## 4.12 Rate limiting

| Endpoint | Límite propuesto |
|---|---|
| `POST /api/v1/admin/auth/login` | 5 intentos por IP cada 15 minutos. |
| `POST /api/v1/admin/users/{id}/change-password` | 3 intentos cada 15 minutos. |
| API pública de catálogo | 100 peticiones por IP cada minuto. |
| Subida de imágenes | 10 archivos por minuto por sesión. |

## 4.13 Password hashing

| Aspecto | Detalle |
|---|---|
| Algoritmo | bcrypt con costo ≥ 12, o Argon2id. |
| Sal | Generada automáticamente por el algoritmo. |
| Política | Mínimo 8 caracteres; mayúscula, minúscula y número recomendados. |
| Cambio forzado | No en v1; opcional en futuro. |

|---|---|

| Futuro | Recuperación por email como extensión. |

## 4.17 Gestión de secretos

| Secreto | Ubicación | Reglas |
|---|---|---|
| `SECRET_KEY` | Variable de entorno | Nunca en repositorio; rotación manual en despliegues. |

- Archivos `.env`.
- Claves privadas.
- Certificados SSL.
- Credenciales de base de datos.
- Tokens de servicios externos.

# 5. Decisiones a cerrar

## SEG-01 — Expiración de sesiones

| Campo | Valor |
|---|---|
| **Identificador** | SEG-01 |
| **Título** | Las sesiones del panel tienen expiración por inactividad y expiración absoluta |
| **Contexto** | `RF-28` exige cierre por inactividad; `AD-37` define sesión de servidor. Falta concretar tiempos. |
| **Decisión** | Expiración por inactividad: **30 minutos**. Expiración absoluta: **12 horas**. |
| **Consecuencias** | Balance entre seguridad y usabilidad para administradores. |

## SEG-02 — Sesiones simultáneas

| Campo | Valor |
|---|---|
| **Identificador** | SEG-02 |
| **Título** | Se permiten múltiples sesiones simultáneas del mismo administrador |
| **Contexto** | Restringir a una sola sesión dificulta el soporte y la administración. |
| **Decisión** | **Sí**, se permiten. Cada sesión tiene identificador propio. El superadministrador puede invalidar sesiones de otros usuarios. |
| **Consecuencias** | Mayor flexibilidad; requiere tabla o almacenamiento de sesiones activas. |

# 6. Amenazas fuera del alcance de la v1

Las siguientes capacidades de seguridad fueron consideradas y deliberadamente pospuestas para versiones futuras:

| Amenaza / Capacidad | Razón de exclusión en v1 |
|---|---|
| **WAF** (Web Application Firewall) | Infraestructura adicional no justificada por el tamaño inicial. |
| **IDS/IPS** | Sobredimensión para una sola instancia. |
| **MFA / 2FA** | Complejidad de onboarding para administradores; se evaluará si el panel crece. |
| **SSO / OAuth** | No hay requisito de integración con proveedores de identidad. |
| **Hardware Security Keys** | Fuera de alcance comercial. |
| **SIEM** | Centralización de logs no requerida en v1. |
| **Antivirus de archivos** | Validación de imágenes por MIME/magic bytes es suficiente en v1. |
| **Escaneo automático de imágenes** | Moderación de contenido no requerida. |
| **Recuperación de contraseña por email** | El superadministrador gestiona contraseñas en v1. |
| **Penetration testing profesional** | No presupuestado en v1; se recomienda antes de escalar. |
