# 2. Objetivo

Definir, **antes de redactar** `07_PANEL_ADMIN.md`, los elementos estructurales del panel administrativo que deben permanecer consistentes con `01_ANALISIS_NEGOCIO.md` y `05_API.md`:

1. Inventario exacto de módulos y trazabilidad con los casos de uso `CU-A-01` a `CU-A-28`.
2. Matriz de permisos por rol.
3. Estados visuales unificados para todos los CRUD.
4. Operaciones que requieren confirmación explícita.
5. Componentes reutilizables que alimentarán `09_COMPONENTES.md`.
6. Árbol de navegación del panel.
7. Mapeo de cada pantalla a los endpoints de `05_API.md`.
8. Decisión arquitectónica explícita: el panel nunca accede directamente al modelo de datos.

---

# 3. Principio rector

> **PAD-01:** El panel administrativo nunca accede directamente al modelo de datos. Toda interacción se realiza exclusivamente mediante los contratos definidos en `05_API.md`.

Esto alinea:

- `04_BASE_DATOS.md` — modelo físico.
- `05_API.md` — contrato de API.
- `06_FRONTEND.md` — filosofía y stack del frontend.
- `07_PANEL_ADMIN.md` — diseño de pantallas y flujos del backoffice.

- **Auditoría** no deriva de un caso de uso `CU-A-XX` individual, sino del requisito transversal `AD-20` y `RF-42`.

# 6. Estados visuales unificados

Cada pantalla de listado, detalle o formulario del panel debe contemplar los siguientes estados visuales:

| Estado | Cuándo ocurre | Qué mostrar |
|---|---|---|
| **Vacío** | La entidad no tiene registros. | Ilustración + mensaje explicativo + CTA principal ("Crear primer ..."). |
| **Cargando** | Primera carga o recarga de datos del servidor. | Esqueleto con la forma aproximada del contenido final; nunca spinner genérico a pantalla completa. |
| **Error** | Fallo de red o error 5xx. | Mensaje de error no técnico, botón de reintentar, y opción de volver al dashboard. |
| **Sin permisos** | El usuario accede a una ruta o intenta una acción no permitida. | Mensaje claro de permisos insuficientes + enlace al dashboard. |
| **Sin resultados** | Hay registros, pero los filtros aplicados no devuelven nada. | Mensaje indicando que no hay coincidencias + botón para limpiar filtros. |
| **Éxito** | Operación de escritura completada. | Toast de confirmación breve; actualización silenciosa de la lista o redirección. |
| **Confirmación** | Operación crítica solicitada. | Diálogo modal con texto explícito de consecuencia y acciones Confirmar/Cancelar. |

### 6.1 Aplicación por tipo de pantalla

| Tipo de pantalla | Estados obligatorios |
|---|---|
| **Listado con tabla** | Vacío, Cargando, Error, Sin resultados, Éxito (tras mutación). |
| **Formulario de creación/edición** | Cargando (carga inicial en edición), Error, Éxito, Confirmación (si abandono con cambios). |
| **Detalle / Vista previa** | Cargando, Error, Sin permisos. |
| **Dashboard** | Cargando, Error, Éxito (no aplica vacío ni sin resultados). |

# 7. Operaciones críticas que requieren confirmación

| Operación | Pantalla / Módulo | Consecuencia | Confirmación |
|---|---|---|---|
| Eliminar producto | Productos / Editar producto | Soft delete (`RN-69`); desaparece del catálogo público. | Modal con nombre del producto. |
| Restaurar producto | Productos (vista de eliminados) | Vuelve a estar disponible para gestión y posible publicación. | Modal de confirmación. |
| Eliminar variante | Ficha de producto → Variantes | La combinación color/talle deja de existir. | Modal con detalle de variante. |
| Eliminar imagen | Ficha de producto → Galería | Soft delete de la fila; el archivo físico se conserva hasta limpieza (`AD-39`). | Modal de confirmación. |
| Cambiar imagen principal | Ficha de producto → Galería | La imagen seleccionada pasa a ser la principal (`RN-20`). | No requiere confirmación; acción reversible inmediata. |
| Eliminar categoría | Categorías | Solo si no tiene productos ni subcategorías (`RN-68`, `AD-24`). | Modal de confirmación. |
| Eliminar marca | Marcas | Solo si no tiene productos (`RN-68`). | Modal de confirmación. |
| Eliminar deporte | Deportes | Solo si no tiene productos (`RN-68`). | Modal de confirmación. |
| Eliminar color | Colores | Solo si no tiene productos ni variantes (`RN-68`). | Modal de confirmación. |
| Eliminar talle | Talles | Solo si no tiene productos ni variantes (`RN-68`). | Modal de confirmación. |
| Eliminar promoción | Promociones | La promoción deja de aplicar. | Modal de confirmación. |
| Restaurar promoción | Promociones (vista de eliminadas) | Vuelve a aplicar si está vigente. | Modal de confirmación. |
| Eliminar banner | Banners | Deja de mostrarse en la página principal. | Modal de confirmación. |
| Cambiar contraseña propia | Perfil / Usuarios | Invalida sesiones activas del usuario. | Modal con solicitud de contraseña actual. |
| Cambiar contraseña de otro usuario | Usuarios | Invalida sesiones activas de ese usuario. | Modal de confirmación (solo Superadministrador). |
| Eliminar usuario | Usuarios | No se puede eliminar al último superadmin (`RN-71`) ni a sí mismo (`RN-72`). | Modal con advertencia especial. |
| Restaurar plantilla por defecto | Plantilla WhatsApp | Sobrescribe la plantilla actual. | Modal de confirmación con recordatorio de que se pierden cambios. |
| Guardar configuración global | Configuración | Afecta datos públicos de la tienda (WhatsApp, dirección, etc.). | No requiere confirmación modal, pero sí feedback de éxito. |

## 9.1 Notas de navegación

- Las rutas se escriben en **español** (`NM-01`).

- La carga del bundle del panel es diferida (`02_ARQUITECTURA.md` §8.5).
- El módulo **Variantes** no aparece en el menú lateral; se accede desde la ficha de producto.

# 11. Hallazgos y puntos de atención
